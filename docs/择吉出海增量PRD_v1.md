## 1. 目标市场优先级

### 1.1 排序与理由

**第一站：新加坡。** ① 华人占比约 74%，简体中文可直接沟通，英文通用，语言包压力最小；② 闽粤择日传统保存完整，婚嫁看通书、开业择日的民俗认知强，教育成本低；③ 支付成熟（信用卡、PayNow、GrabPay 均可经 Stripe 覆盖）；④ PDPA 框架清晰，隐私合规路径明确；⑤ 课帖「海风」版式（v3.5 §12.4）即为此市场设计。

**第二梯队：马来西亚。** 中文教育体系完整，华人约 23%，民俗保留度甚至高于新加坡；MYR 客单价需按购买力平价下调；需兼容部分繁体中文使用者（P1 补繁体包）。

**第三梯队：北美（美国、加拿大）。** 华人密度高、客单价承受力最强（USD 定价最高）、婚嫁与开业场景真实存在；但中文使用率下降明显，英文语言包价值最大；节庆场景（如北美中元节、清明跨城祭祖）有增量空间。

**第四梯队：欧洲、澳洲、其他东南亚（泰国、印尼、越南）。** 华人社群规模或中文能力受限，经首站验证后按自然流量与兑换码运营数据决定投入；泰文/越南文语言包维持 v3.5 §15 的规划（P2），不在出海首版范围。

### 1.2 排序逻辑（可复用的判据）

市场优先级 = 华人密度 × 民俗保存度 × 中文可用性 × 支付成熟度 ÷ 语言与合规成本。按此判据，东南亚整体优先于欧美；在东南亚内，新加坡的综合分最高。

## 2. 语言策略

### 2.1 决策：简体中文 + 英文双语言包，出海首版即交付

v3.5 §12.5 规定产品内中文单语、英文版规划在 v5.0。出海提前后，**英文 UI 语言包升级为 P0，随出海 H5 首版交付**，理由：① 北美、欧洲华人与第二代移民中文能力有限，英文是触达增量用户的前提；② 界面框架英文化是低成本工程（文案外置语言包），真正的成本在术语表与知库翻译，可分层交付。

语言包分层交付：

| 层 | 内容 | 优先级 |
|---|---|---|
| L1 界面层 | 全部界面文案、按钮、空状态、免责声明 | P0 中英双语 |
| L2 交付物层 | 九章报告框架标题、课帖骨架文字、AI 解读四段结构 | P0 英文 |
| L3 知识层 | 知库文章、典籍提要 | P1 首批 10 篇（择日学理 5 篇 + 婚嫁礼制 3 篇 + 餐饮/工程各 1 篇），其余 P2 分批 |
| L4 其他语种 | 繁体中文（兼容大马/港澳） | P1 |
| L4 其他语种 | 泰文/越南文/韩文/日文 | P2，维持 v3.5 §15 规划 |

**繁简体决策**：产品默认简体中文。繁体中文包 P1 交付，用于大马与港澳用户；不因地区自动切换，由「语言与地区」屏手动选择（v3.5 原型 rLang 已有语言选择器，直接扩展）。

### 2.2 术语英译原则（六条）

1. **一概念一译名**：全部英文术语集中在术语表维护（对齐 v3.5 §03 口径），产品界面、报告、AI 解读、知库四处共用，禁止各处手写。
2. **音译 + 意译双轨**：核心择日术语首次出现采用「拼音（英文释义）」格式，如 建除十二值神 → Jianchu Twelve Day Officers（建除十二值神）。拼音建立品牌辨识，释义保证可理解。
3. **干支系统保留拼音 + 释义**：天干地支、四柱、六十甲子不直译，用罗马拼音（Jiazi、Bingwu）配英文释义（e.g. "Year Pillar"），保证专业用户可核对。
4. **释义优先于直译**：直译会产生歧义时取释义。如「黄历」不译 Yellow Calendar（英文语境含贬义且与通书混淆），统一译 Tong Shu / Huangli Almanac 并在术语表注明区别。
5. **结果性表述的英文红线同样成立**： guaranteed luck、prosperity、ward off evil 等词与中文「大吉」「必发财」同级禁止；AI 英文输出受同一套五条硬边界约束（v3.5 §08）。
6. **历法与数字格式本地化**：日期格式随地区（美国月/日/年，其余日/月/年）；干支纪年与公元并排（2026 ／ Bingwu Year）；时辰注明东八区口径（见 §6.1）。

## 3. 免注册免登录的产品形态

v3.5 的付费与配额体系隐含账号体系（月度配额重置、次数随账号）。免登录后全部改为**设备维度 + 本地优先**，同时为后期 APP 账号合并预留迁移协议。

### 3.1 AI 解读配额：本地配额 + 设备维度（P0）

| 项 | v3.5（账号制） | 出海 H5（免登录） |
|---|---|---|
| 免费额度 | 3 次/月，每月 1 日重置 | 3 次/月不变，按**用户所选时区的自然月**滚动重置 |
| 配额存储 | 服务端账号字段 | 本机存储：`{freeLeft, monthKey, paidLeft}` |
| 重置判定 | 服务端定时 | 打开 AI 页时比对 monthKey，跨月即重置 freeLeft |
| 追问 | 同计 1 次 | 不变 |
| 解读复用 | 同一课期同一版本不重复生成 | 不变，且解读结果本机缓存（顺带降低海外推理链路成本） |

**设备维度的已知风险与对策**：清除浏览器数据、换设备、换浏览器即失效，用户感知为「额度/购买丢失」。对策：① 购买凭证与档案均提供**导出**（见 3.3）；② 兑换码可重新绑定设备（见 4.2）；③ 排课与逐层依据始终免费（v3.5 §08 原则不变），配额只约束 AI 解读，不造成功能阻断。接受小规模滥用作为免登录的代价：AI 解读有复用缓存与月配额双重上限，单设备成本可控。

### 3.2 付费解锁：一次性购买制（P0）

**主推方案：一次性购买 + 本地凭证。** 购买成功后在回跳 URL 携带兑换凭证（license code），H5 本地存储 `{code, sku, left, boundAt}`，解锁态即时生效。SKU 沿用 v3.5 §08.1 四档（单次课期报告 / AI 解读包 / 嫁娶双人包 / 年卡），**取消「月卡」类订阅制**——订阅在无账号体系下无法可靠续费，且退款纠纷风险高。

**备选方案（按序）**：
1. **兑换码人工发放**：面向社群运营场景（会馆、婚庆服务商、KOL 渠道），批量购码后分发。同时承担「换设备恢复」的兜底功能。
2. **PayPal 支付链接**：Stripe 未覆盖地区的补充渠道。

**后期 APP 账号合并策略（设计预留，APP 阶段实施）**：H5 导出的迁移包内包含 license code 列表；APP 注册登录后导入，同 code 在服务端核验并绑定到账号，实现「免登录购买 → 账号内继续用」。code 设计为**可迁移一次**（绑定新设备时旧设备解绑），防止无限扩散。

### 3.3 数据持久化：本地优先 + 可导出 + 可合并（P0 设计，P1 完整实现）

| 层 | 方案 |
|---|---|
| 存储 | IndexedDB 为主（档案、课期历史、收藏、凭证），localStorage 降级兼容；容量与异步读写满足课期历史增长 |
| 实体 | 沿用 v3.5 §13 六实体（Person / Industry / Event / Day / Layer / Scan / Report / AiQuota），**新增两个本机实体**：License（购买凭证）与 Settings（语言、时区、币种、历法显示） |
| 版本 | 每条记录带 `schemaVersion`；语言包、汇率、业态表随发布版本，本机缓存 |
| 导出 | 「我的 → 导出档案」生成 `zj-backup-v1.json`（含 Person、Scan、收藏、License）；另提供课帖长图导出（分享物） |
| 导入 | 同一格式导入，按 `personId` 去重合并；导入即 H5→APP 的迁移协议，APP 阶段复用为账号合并接口的 payload 格式 |

**隐私口径适配（关键变更）**：v3.5 §4.1 的「出生资料仅存于本机浏览器（localStorage）」表述在海外升级为：出生资料**仅存于本机、不传输、不上传**；页面底部固定说明保留；导出文件由用户本机自行生成与保管，产品不经手。删除权：清除本机数据 = 彻底删除，无服务端残留（这也是免登录对 GDPR/PDPA 的结构性优势，见 §5）。

### 3.4 APP 扩展预留（架构约束，交架构师）

产品层面的硬约束：① H5 必须是可安装的 PWA（manifest + 离线可用），让「加主屏」成为 APP 前的自然一步；② 响应式以移动端为基准（v3.5 §15 的 390×844 不变），平板与桌面做可用性适配而非重新设计；③ 数据访问必须经仓库层抽象，禁止业务代码直接操作存储 API，保证 APP 阶段可切换到账号云同步。除此之外的技术选型由架构师决定。

## 4. 支付与货币

### 4.1 多币种定价表（P0）

以 v3.5 §08.1 人民币价（¥29 / ¥19 / ¥49 / ¥199）为锚，按购买力平价与本地心理价位取整：

| SKU | CNY | USD | SGD | MYR | THB |
|---|---|---|---|---|---|
| 单次课期报告 | ¥29 | $6.9 | S$9.9 | RM32.9 | ฿249 |
| AI 解读包（10 次） | ¥19 | $4.9 | S$6.9 | RM21.9 | ฿169 |
| 嫁娶双人包 | ¥49 | $11.9 | S$15.9 | RM54.9 | ฿429 |
| 年卡 | ¥199 | $39.9 | S$52.9 | RM169.9 | ฿1,399 |

定价逻辑：① USD 高于人民币锚的直换算（$6.9 vs ¥29≈$4），体现北美客单价承受力与心理价位（$x.9）；② SGD 按汇率上浮取整（S$9.9）；③ MYR/THB 按购买力平价下调，低于直换算，保证东南亚转化率不因价格流失；④ 全部以 .9 结尾，符合各市场习惯。汇率与价格表随发布版本更新（v3.5 §15 多币种要求沿用），不实时取汇率——免登录无服务端，取实时汇率会引入失败点。

币种默认值：按 IP/浏览器地区推断默认币种，「语言与地区」屏可手动改（v3.5 原型 rLang 已有币种切换器，接入真实价格表）。

### 4.2 支付渠道：主推 Stripe Payment Link（P0）

| 渠道 | 角色 | 理由 |
|---|---|---|
| **Stripe Payment Link** | **主推** | 免登录即可用（无账号也能收单）；一链接一 SKU 一币种，前端按用户选择跳转；支持卡组织 + Apple Pay / Google Pay + 各地本地方式（PayNow、GrabPay、PromptPay 等经 Stripe 覆盖）；卡数据不落地，合规负担最小；购买完成回跳 H5 并携带凭证参数 |
| PayPal | 备选 | Stripe 未覆盖地区与部分用户习惯；同样免登录可用 |
| 兑换码人工发放 | 运营渠道 + 兜底 | 社群/服务商批量分发；换设备恢复购买；上线初期 Stripe 审核期可先行营业 |

不采用的方案：需要登录态的订阅网关（无账号体系下不可靠）；应用商店内购（H5 阶段不适用，APP 阶段若上架再议，注意 H5 内引导至站外支付在各商店政策下的合规边界，由 APP 阶段评估）。

购买流程（免登录闭环）：选 SKU → 选币种 → 跳 Stripe Checkout → 支付成功回跳 `?license=XXXX` → H5 本地写凭证 → 解锁态即时生效（报告全文/AI 次数）。失败与取消回跳带回错误码，页面给出重试与「输入兑换码」两个出路。

## 5. 出海合规与免责

### 5.1 产品定位声明（全站固定，随语言包本地化）

沿用 v3.5 页脚口径，英文化后作为统一免责：

> 本产品提供传统择日规则的工程化推演，属民俗文化参考，不预测结果、不承诺吉凶、不涉及医疗与投资建议。
> This product presents an engineered application of traditional date-selection rules for cultural reference only. It does not predict outcomes, promise fortune, or provide medical or investment advice.

英文版同样执行结果性词汇红线（§2.2 第 5 条），AI 英文输出的五条硬边界与中文版一致（v3.5 §08）。

### 5.2 隐私政策要点（GDPR / PDPA 适配）

| 法规关注点 | 产品现状与表述 |
|---|---|
| 出生日期、时刻、地点属个人数据 | 仅存用户本机（IndexedDB），**不传输、不上传、不建服务端档案**——这是免登录架构的结构性合规优势，政策中明确写出 |
| 数据最小化 | 产品不收集手机号、邮箱、精确地理位置；出生地为用户自选城市（非 GPS 定位） |
| 被遗忘权 / 删除权 | 「我的 → 清除本机数据」一键彻底删除，无服务端残留需另行申请 |
| 可携带权 | 导出 `zj-backup-v1.json` 由用户自行保管 |
| Cookie 与追踪 | H5 不使用广告追踪 SDK；如使用匿名统计（P1 评估），仅限聚合事件，政策中声明 |
| 支付数据 | 卡信息由 Stripe/PayPal 处理，产品不存储任何支付凭证，仅存兑换 code |
| 儿童数据 | 剖腹产择日等用事涉及婴儿信息，同样仅本机存储；不主动面向 13 岁以下单独收集 |

### 5.3 H5 合规（无应用商店场景）

## 7. 海外华人场景增量

### 7.1 时区：「今日」与吉时的双口径决策（P0）

核心矛盾：海外用户的「今天」在本地，但干支、节气、时辰的择日口径在全球是统一的。

**决策：双口径分离。**
- **「今日」判定**：以用户所选时区为准。默认取浏览器时区，首启与「语言与地区」屏可手动切换（复用 v3.5 原型 rLang 时区选择器，补齐西五区及以后、南半球时区）。首页通书宜忌、课期区间起点、月配额重置（3.1）均用此时区。
- **四柱、节气、日课吉时判定**：一律按**东八区（北京时间）口径**计算——节气交接、月建以「节」为界、时辰归属都是中国历法体系的定义，跨时区平移会破坏可核对性。界面在吉时旁固定标注「时辰为东八区口径」，并给出用户本地时刻作为**信息性参考**（不改判定）。例：吉时「午时（11:00–13:00 东八区）」旁注「洛杉矶时间 20:00–22:00（前一日）」。
- 此口径写入报告第一章「结论口径」，中英双语明示，避免海外用户拿本地时间与界面时间对不上而产生「算错了」的质疑。

### 7.2 真太阳时与海外出生地（P0）

- v3.5 §4.1 的经度校正机制不变：档案存**原始钟表时刻 + 出生地**，真太阳时读取时重算。海外用户出生时刻多为本地钟表时间，出生地经度决定校正量（如温哥华与北京经度差约 3 小时 20 分）。
- **出生地数据扩展**：内置城市经纬度表新增海外华人聚居城市约 40 个——新加坡、吉隆坡、槟城、曼谷、清迈、雅加达、泗水、胡志明市、河内、马尼拉、温哥华、多伦多、卡尔加里、旧金山、洛杉矶、圣迭戈、西雅图、纽约、波士顿、休斯顿、芝加哥、伦敦、曼彻斯特、悉尼、墨尔本、奥克兰等；每城预填时区（时区仅作显示参考，校正只用经度）。
- **兜底**：城市不在列表时提供手动输入经纬度（带格式校验与实时四柱预览，v3.5 §4.1 预览能力复用）；输入框明示「只填城市，不需要精确住址」。
- 数据边界：城市表为静态内置数据，不调用地理编码 API（保持单文件离线可用，v3.5 §15）。

### 7.3 节日与地区场景（P1/P2）

- **节庆参考标记（P1）**：课期日历上以信息性标记显示主要公共假日与华人传统节日（农历新年、清明、中元、重阳；北美感恩节/圣诞节、各地农历新春公假等）。原则：标记**不进入计分、不影响评分**——产品不讲吉凶也不做节日营销日历，只帮用户避开「日子合课但全城放假」的冲突（如婚礼撞公共假日、开业撞店休日）。节日表按用户所选地区显示，随设置切换。
- **北美社群场景选题（P2）**：知库新增选题方向——「海外结婚，日子按哪边算」（时区与口径）、「跨国婚礼的双方行嫁月」「二代华人家庭：长辈的通书与你的课帖」。以知库内容承接，不改引擎。
- **清明/中元跨时区祭祖**：归入 v3.5 已有「祭祀安葬」用事，无需新用事；仅在知库补充时区口径说明（P2）。

`lang_set{lang}` · `tz_set{tz}` · `cur_set{cur}` · `pay_redirect{sku,cur}` · `pay_return{license,ok}` · `code_redeem{ok}` · `backup_export{}` · `backup_import{ok,people}` · `share_ref{code}`。全部匿名本机事件，不含出生资料字段。
